# Sync Phase B — Entities, Push/Pull, Attachments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a generic per-user sync relay (`entities` table + `/sync/push` + `/sync/pull`) and binary attachment upload/download to the `unitask-sync-server` backend, so a future client-side sync engine has a working server to talk to.

**Architecture:** The server does not model tasks/subjects/etc. as distinct relational tables — it stores every synced row as an opaque `(userId, table, entityId) -> payload` JSON blob in one `entities` table, exactly as specified in `docs/superpowers/specs/2026-09-12-multi-device-sync-design.md` §5.2. Conflict resolution is last-write-wins by client-supplied `clientUpdatedAt`, compared server-side per entity — no field-level merge, no conflict UI. The pull cursor is a DB-native monotonic `bigserial` (`serverSeq`), not a timestamp, to avoid clock-sync issues across devices. Attachment metadata (filename, mime, size, taskId) travels through the same `entities` push/pull path as any other row (`table: "attachments"`); only the binary bytes go through two dedicated multipart endpoints, which look up the row's own metadata to know where to store/serve the file. This phase is server-only — no client-side sync engine, no UI, no mobile-app changes.

**Tech Stack:** Fastify 5, Drizzle ORM 0.45 (`drizzle-orm/pg-core`), PostgreSQL, `@fastify/multipart` (new dependency, installed in Task 5), Jest + `ts-jest` against a real Postgres test database (no mocking).

## Global Constraints

- No lint/prettier is configured in this repo (unlike the main UniTask app) — verification after each task is `npm run build` (tsc) + `npm test` only.
- Every repository function takes `database: Database = defaultDb` (`type Database = typeof defaultDb` from `../db/client`) so tests inject the real Postgres test DB — never mock the DB, per this repo's established convention.
- Every `/sync/*` route requires the existing `requireAuth` preHandler from `src/auth/middleware.ts` and scopes every query by `request.userId`.
- IDs are `text` UUIDs generated app-side via `randomUUID()` from `"crypto"`, matching `users`/`refreshTokens` — except `entities.serverSeq`, a DB-native `bigserial`, which is a deliberate deviation because it must be a database-assigned monotonic sequence to serve as the pull cursor (spec §5.2, "avoids clock-sync issues").
- Out of scope for this phase (per the design spec, explicitly deferred): the client-side sync engine (`src/lib/sync/` in the UniTask app), multi-user accounts, real-time/WebSocket propagation, conflict-surfacing UI, and object storage (attachments stay on local disk at this scale).
- Migrations: run `npm run db:generate` (drizzle-kit) to produce the SQL file from the schema change, then commit the generated file under `drizzle/`. Apply with `npm run db:migrate:dev` locally/in tests, `npm run db:migrate` in production.
- Test DB env: `DATABASE_URL_TEST` (falls back to `postgres://postgres:postgres@localhost:5432/unitask_sync_test` per `jest.setup.ts`) — already provisioned from Phase A, no new database needed.

```typescript
export const users = pgTable("users", {
  id: text("id").primaryKey(),
  email: text("email").notNull().unique(),
  passwordHash: text("password_hash").notNull(),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
});

export const refreshTokens = pgTable("refresh_tokens", {
  id: text("id").primaryKey(),
  userId: text("user_id")
    .notNull()
    .references(() => users.id, { onDelete: "cascade" }),
  tokenHash: text("token_hash").notNull(),
  expiresAt: timestamp("expires_at", { withTimezone: true }).notNull(),
  revokedAt: timestamp("revoked_at", { withTimezone: true }),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
});

export const entities = pgTable(
  "entities",
  {
    serverSeq: bigserial("server_seq", { mode: "number" }).primaryKey(),
    userId: text("user_id")
      .notNull()
      .references(() => users.id, { onDelete: "cascade" }),
    entityTable: text("entity_table").notNull(),
    entityId: text("entity_id").notNull(),
    payload: jsonb("payload"),
    deleted: boolean("deleted").notNull().default(false),
    updatedAt: bigint("updated_at", { mode: "number" }).notNull(),
  },
  (table) => [
    unique("entities_user_table_entity_unique").on(table.userId, table.entityTable, table.entityId),
  ],
);

export type User = typeof users.$inferSelect;
export type NewUser = typeof users.$inferInsert;
export type RefreshToken = typeof refreshTokens.$inferSelect;
export type NewRefreshToken = typeof refreshTokens.$inferInsert;
export type Entity = typeof entities.$inferSelect;
export type NewEntity = typeof entities.$inferInsert;
```

**Note (found in review):** a plain `UPDATE` never advances a `bigserial` column — only `INSERT` does. Without the explicit `serverSeq: sql\`nextval(...)\`` reassignment above, an edit or delete of an already-pulled entity would never reach a device whose cursor already passed that row's original `serverSeq`. The code and test above already include the fix.

```typescript
import { and, asc, eq, gt, sql } from "drizzle-orm";

import { db as defaultDb } from "../db/client";
import { entities, type Entity } from "../db/schema";

type Database = typeof defaultDb;

export interface SyncOperation {
  table: string;
  entityId: string;
  operation: "upsert" | "delete";
  payload: unknown;
  clientUpdatedAt: number;
}

export interface PushResult {
  accepted: string[];
  rejected: string[];
}

export interface PullResult {
  operations: SyncOperation[];
  cursor: number;
}

export async function pushOperations(
  userId: string,
  operations: SyncOperation[],
  database: Database = defaultDb,
): Promise<PushResult> {
  const accepted: string[] = [];
  const rejected: string[] = [];

  for (const op of operations) {
    const key = `${op.table}:${op.entityId}`;
    const existing = await getEntity(userId, op.table, op.entityId, database);

    if (existing && existing.updatedAt > op.clientUpdatedAt) {
      rejected.push(key);
      continue;
    }

    const deleted = op.operation === "delete";
    const payload = deleted ? null : op.payload;

    if (existing) {
      await database
        .update(entities)
        .set({
          payload,
          deleted,
          updatedAt: op.clientUpdatedAt,
          serverSeq: sql`nextval(pg_get_serial_sequence('entities', 'server_seq'))`,
        })
        .where(eq(entities.serverSeq, existing.serverSeq));
    } else {
      await database.insert(entities).values({
        userId,
        entityTable: op.table,
        entityId: op.entityId,
        payload,
        deleted,
        updatedAt: op.clientUpdatedAt,
      });
    }
    accepted.push(key);
  }

  return { accepted, rejected };
}

export async function pullOperations(
  userId: string,
  since: number,
  database: Database = defaultDb,
): Promise<PullResult> {
  const rows = await database
    .select()
    .from(entities)
    .where(and(eq(entities.userId, userId), gt(entities.serverSeq, since)))
    .orderBy(asc(entities.serverSeq));

  const syncOperations: SyncOperation[] = rows.map((row) => ({
    table: row.entityTable,
    entityId: row.entityId,
    operation: row.deleted ? "delete" : "upsert",
    payload: row.deleted ? null : row.payload,
    clientUpdatedAt: row.updatedAt,
  }));

  const cursor = rows.length > 0 ? rows[rows.length - 1].serverSeq : since;

  return { operations: syncOperations, cursor };
}

export async function getEntity(
  userId: string,
  table: string,
  entityId: string,
  database: Database = defaultDb,
): Promise<Entity | null> {
  const [row] = await database
    .select()
    .from(entities)
    .where(and(eq(entities.userId, userId), eq(entities.entityTable, table), eq(entities.entityId, entityId)))
    .limit(1);
  return row ?? null;
}
```

```typescript
import { FastifyInstance } from "fastify";

import { requireAuth } from "../auth/middleware";
import { pushOperations, pullOperations, type SyncOperation } from "./entities-repository";

interface PushBody {
  operations: SyncOperation[];
}

interface PullQuery {
  since?: string;
}

export async function syncRoutes(app: FastifyInstance) {
  app.post<{ Body: PushBody }>(
    "/sync/push",
    { preHandler: requireAuth },
    async (request, reply) => {
      const result = await pushOperations(request.userId!, request.body.operations);
      return reply.send(result);
    },
  );

  app.get<{ Querystring: PullQuery }>(
    "/sync/pull",
    { preHandler: requireAuth },
    async (request, reply) => {
      const since = Number(request.query.since ?? 0);
      const result = await pullOperations(request.userId!, since);
      return reply.send(result);
    },
  );
}
```

```typescript
import { existsSync } from "fs";
import { mkdir, readFile, writeFile } from "fs/promises";
import path from "path";

import { config } from "../config";

export function attachmentPath(
  userId: string,
  taskId: string,
  attachmentId: string,
  fileName: string,
  baseDir: string = config.attachmentsDir,
): string {
  const safeName = fileName.replace(/[/\\]/g, "");
  return path.join(baseDir, userId, taskId, `${attachmentId}-${safeName}`);
}

export async function saveAttachmentFile(destPath: string, content: Buffer): Promise<void> {
  await mkdir(path.dirname(destPath), { recursive: true });
  await writeFile(destPath, content);
}

export async function readAttachmentFile(filePath: string): Promise<Buffer> {
  return readFile(filePath);
}

export function attachmentFileExists(filePath: string): boolean {
  return existsSync(filePath);
}
```

```typescript
import { FastifyInstance } from "fastify";

import { requireAuth } from "../auth/middleware";
import { getEntity } from "./entities-repository";
import { attachmentPath, attachmentFileExists, readAttachmentFile, saveAttachmentFile } from "./attachment-storage";

export interface AttachmentPayload {
  taskId: string;
  originalFileName: string;
  mimeType: string;
  sizeBytes: number;
}

export async function attachmentRoutes(app: FastifyInstance) {
  app.post<{ Params: { attachmentId: string } }>(
    "/sync/attachments/:attachmentId",
    { preHandler: requireAuth },
    async (request, reply) => {
      const entity = await getEntity(request.userId!, "attachments", request.params.attachmentId);
      if (!entity || entity.deleted || !entity.payload) {
        return reply.status(404).send({ error: "Attachment metadata not found" });
      }
      const metadata = entity.payload as AttachmentPayload;

      const data = await request.file();
      if (!data) {
        return reply.status(400).send({ error: "No file uploaded" });
      }
      const buffer = await data.toBuffer();

      const destPath = attachmentPath(
        request.userId!,
        metadata.taskId,
        request.params.attachmentId,
        metadata.originalFileName,
      );
      await saveAttachmentFile(destPath, buffer);
      return reply.send({ ok: true });
    },
  );

  app.get<{ Params: { attachmentId: string } }>(
    "/sync/attachments/:attachmentId",
    { preHandler: requireAuth },
    async (request, reply) => {
      const entity = await getEntity(request.userId!, "attachments", request.params.attachmentId);
      if (!entity || entity.deleted || !entity.payload) {
        return reply.status(404).send({ error: "Attachment metadata not found" });
      }
      const metadata = entity.payload as AttachmentPayload;

      const filePath = attachmentPath(
        request.userId!,
        metadata.taskId,
        request.params.attachmentId,
        metadata.originalFileName,
      );
      if (!attachmentFileExists(filePath)) {
        return reply.status(404).send({ error: "Attachment file not found" });
      }
      const content = await readAttachmentFile(filePath);
      return reply.type(metadata.mimeType).send(content);
    },
  );
}
```

**Note (found in whole-branch review after Task 6, fixed after deployment — a real Critical, live in production):** the `attachmentPath()` implementation shown in Task 4 Step 4 only ever sanitizes `fileName`. This task hands two MORE attacker-controlled inputs to that same function — `metadata.taskId` (arbitrary client JSON, pushed via `/sync/push`, never validated) and `attachmentId` (a raw URL path param) — without extending the sanitization to cover them. A payload like `taskId: "../../../ESCAPED"` writes/reads files outside `ATTACHMENTS_DIR` entirely. Each per-task review judged its own task against its own brief correctly; only the whole-branch view caught this composition gap. **The actual fix**: `attachmentPath()` must reject (not merely strip) `taskId` and `attachmentId` if they are empty, `.`, `..`, or contain `/`/`\` — see `src/sync/attachment-storage.ts`'s `assertSafePathSegment`/`PathTraversalError` in the deployed repo for the real, tested implementation. A future phase reusing this pattern (e.g. a new entity type with its own attacker-controlled path component) must sanitize every path segment that isn't hardcoded, not just the filename.
